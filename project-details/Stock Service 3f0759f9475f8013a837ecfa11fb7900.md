# Stock Service

## Суть сервиса

Stock Service отвечает за проверку наличия товара и его резервирование для конкретного заказа.

После создания заказа Order Service отправляет данные о товаре в Stock Service. Stock Service принимает этот запрос, проверяет, можно ли зарезервировать нужное количество товара, сохраняет результат в собственной базе данных и передаёт данные дальше в Payment Service.

Для учебного проекта проверку наличия можно сделать максимально простой. Например, считать, что товар доступен, если количество не превышает 5 единиц.

Stock Service не создаёт заказы, не проводит оплату и не занимается доставкой. Его задача — только обработать резервирование товара.

---

## API, которые предоставляет Stock Service

### Создание резервирования

`POST /reservations`

Этот API вызывает Order Service после создания нового заказа.

Request:

```
{
  "order_id": 1,
  "product_name": "Pizza",
  "quantity": 2,
  "amount": 1000
}
```

Stock Service должен:

- проверить количество товара;
- создать запись о резервировании в базе данных;
- определить статус резервирования;
- при успешном резервировании вызвать Payment Service.

Пример успешного Response:

```
{
  "reservation_id": 10,
  "order_id": 1,
  "status": "reserved"
}
```

Пример Response при отказе:

```
{
  "reservation_id": 10,
  "order_id": 1,
  "status": "rejected"
}
```

Допустимые статусы:

```
reserved
rejected
```

---

### Получение резервирования

`GET /reservations/{id}`

Используется для получения информации о конкретном резервировании.

Пример:

`GET /reservations/10`

Response:

```
{
  "id": 10,
  "order_id": 1,
  "product_name": "Pizza",
  "quantity": 2,
  "amount": 1000,
  "status": "reserved"
}
```

---

### Получение списка резервирований

`GET /reservations`

Используется для просмотра всех резервирований.

Response:

```
[
  {
    "id": 10,
    "order_id": 1,
    "product_name": "Pizza",
    "quantity": 2,
    "amount": 1000,
    "status": "reserved"
  },
  {
    "id": 11,
    "order_id": 2,
    "product_name": "Burger",
    "quantity": 8,
    "amount": 2400,
    "status": "rejected"
  }
]
```

---

## API, которое Stock Service вызывает

Если товар успешно зарезервирован, Stock Service должен вызвать Payment Service.

`POST /payments`

Request:

```
{
  "order_id": 1,
  "amount": 1000
}
```

Ожидаемый Response от Payment Service:

```
{
  "payment_id": 25,
  "order_id": 1,
  "status": "paid"
}
```

Если резервирование завершилось со статусом `rejected`, Payment Service вызывать не нужно.

---

## Бизнес-логика

Для упрощения можно использовать такое правило:

```
quantity <= 5 → reserved
quantity > 5 → rejected
```

Например:

```
quantity = 2
status = reserved
```

А если:

```
quantity = 8
status = rejected
```

## Таблица базы данных

Stock Service использует собственную таблицу `reservations`.

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | integer | Уникальный идентификатор резервирования |
| `order_id` | integer | Идентификатор заказа из Order Service |
| `product_name` | string | Название товара |
| `quantity` | integer | Количество товара |
| `amount` | integer | Общая стоимость заказа |
| `status` | string | Статус резервирования |

Пример записи:

```
id: 10
order_id: 1
product_name: Pizza
quantity: 2
amount: 1000
status: reserved
```

Пример в JSON:

```
{
  "id": 10,
  "order_id": 1,
  "product_name": "Pizza",
  "quantity": 2,
  "amount": 1000,
  "status": "reserved"
}
```

Таким образом, Stock Service принимает данные о заказе от Order Service, проверяет возможность резервирования товара, сохраняет результат в своей базе данных и при успешном резервировании передаёт данные дальше в Payment Service.
