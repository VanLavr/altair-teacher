# Простой клиент заказов

Откройте `index.html` двойным щелчком в браузере. HTML, CSS и JavaScript лежат
рядом; сервер для страницы, сборщик, npm и доступ в интернет не нужны.

1. Запустите backend и перезапустите Order Service после обновления его кода.
2. Откройте `index.html` и укажите адрес Order Service. Для одной машины —
   `http://127.0.0.1:8000`, для Wi-Fi сети — IP компьютера команды Order и порт.
3. Создайте заказ. POST ожидает прохождения всей цепочки; результат и список
   появятся после ответа API. Пока запрос выполняется, кнопки отключены.
4. Используйте «Обновить список» или поиск по ID, чтобы проверить состояние.

Примеры: 2 товара по 500 ₽ проходят всю цепочку; 6 товаров дают отказ склада;
1 товар за 5001 ₽ даёт отказ оплаты. `failed` — сохранённый заказ с отказом,
HTTP 502 — ошибка взаимодействия сервисов. Сообщение 502 показывает ID заказа,
если API его вернул. После сетевого сбоя проверьте список перед повторным POST.

Страница использует только `POST /orders`, `GET /orders` и `GET /orders/{id}`.
Список показывает первые 1000 записей в порядке ID; любой другой заказ доступен
через поиск. Новые обращения к соседям запускает сам Order Service.

В Order Service добавлен CORSMiddleware. Для страницы `file://` браузер посылает
`Origin: null`, поэтому в `demo-orders/app.env` предусмотрено:

```dotenv
CORS_ORIGINS=null
```

Если страницу позднее разместят на HTTP-сервере, добавьте его origin через
запятую, например `CORS_ORIGINS=null,http://localhost:8080`, и перезапустите Order.
Это настройка учебного локального API. Адрес страницы и адрес API — разные origins.

При ошибке связи проверьте доступность `http://IP:ПОРТ/docs`, адрес API,
CORS и разрешение входящих подключений в брандмауэре. Если браузер запросит
разрешение доступа страницы к локальной сети, разрешите его для занятия.
