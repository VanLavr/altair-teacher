# Order Service

Самостоятельный учебный микросервис. Эту директорию можно целиком перенести
в отдельный репозиторий: общий код, файлы или Python-пакеты соседних проектов
не требуются. Нужны Python 3.11+ и доступ к общей PostgreSQL `orders_db`.

## Запуск команды

1. Откройте терминал в корне своего репозитория.
2. Заполните `app.env`: адрес общей базы и IP:port нужных соседей.
3. Выполните `make run` и оставьте терминал открытым.

Пример настроек для разных компьютеров одной Wi-Fi сети:

```dotenv
DATABASE_URL=postgresql://orders:1234@192.168.1.10:5433/orders_db
APP_HOST=0.0.0.0
APP_PORT=8000
STOCK_SERVICE_URL=192.168.1.11:8001
```

Это пример IP-адресов. Замените их фактическими адресами компьютеров в вашей сети.
Включённый `app.env` изначально настроен для запуска всех сервисов на одном
компьютере. `127.0.0.1` всегда обозначает ваш компьютер, а не соседнюю команду.
Можно указать `ip:port` или `http://ip:port`; приложение добавит `http://`, если
схема не указана. Переменные окружения имеют приоритет над файлом.
После изменения `app.env` перезапустите приложение.

`APP_HOST=0.0.0.0` позволяет принимать запросы с соседних компьютеров.
У себя откройте http://127.0.0.1:8000/docs, у соседей —
`http://IP_ЭТОГО_КОМПЬЮТЕРА:8000/docs`. `0.0.0.0` не является адресом для браузера.
Разрешите входящие TCP-подключения на `APP_PORT` в брандмауэре компьютера.
Wi-Fi должен разрешать обмен между клиентами (без изоляции устройств).

Если `make` недоступен, на Linux/macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

На Windows (PowerShell):

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

Ctrl+C останавливает только ваш сервис. Docker для приложения не нужен.
`run.py` берёт адрес прослушивания и порт из `app.env`.

## Слои

```text
orders_app/
├── config.py               # Настройки именно этого проекта
├── main.py                 # Сборка зависимостей и FastAPI-приложения
├── controller/             # HTTP-маршруты, DTO и проверка полей
│   ├── routes.py
│   ├── schemas.py
│   ├── fields.py
│   └── parameters.py
├── service/                # Бизнес-правила и интерфейсы зависимостей
│   ├── logic.py
│   └── ports.py
├── downstreams/            # HTTP-вызовы соседних сервисов
│   ├── clients.py
│   └── http.py
├── repository/             # SQL только для таблицы orders
│   ├── records.py
│   └── postgres.py
└── models/                 # Доменные dataclass и ошибки приложения
    ├── domain.py
    └── errors.py
```

`controller` преобразует входной DTO в `OrderData` и передаёт его в `service`.
Бизнес-слой принимает решение и вызывает интерфейсы `repository`/`downstreams`.
Repository возвращает доменную модель `Order`. Service не импортирует
FastAPI, Pydantic, httpx или psycopg. У каждого слоя есть русские комментарии.

## Проверки

```bash
make test
```

Тесты проверяют бизнес-правила, ошибки соседей и настройки без PostgreSQL
и реальных HTTP-запросов. Для проверки связи откройте `/health` своего сервиса
с другого компьютера: HTTP 200 означает доступность приложения и его таблицы
в общей базе. `/docs` проверяет только доступ к веб-приложению.

API: `POST /orders`, `GET /orders`, `GET /orders/{id}`.
Order Service также предоставляет `PATCH /orders/{id}/status`.
У промежуточных сервисов POST предполагает существующий `order_id`.
Для полного сценария запустите все пять сервисов и создайте заказ в Order Service.

## База данных

На занятии PostgreSQL размещается на одном компьютере, а все команды указывают
один `DATABASE_URL`. Используйте базу `orders_db`, пользователя `orders`, пароль
`1234`. Администратор заранее создаёт все пять таблиц. Эта команда работает
только с таблицей `orders`, но SQL-клиентом можно посмотреть всю общую базу.

Создание базы, пользователя, таблиц и все миграции выполняет преподаватель
отдельным инфраструктурным скриптом. В этом репозитории нет Docker-команд,
SQL-миграций или инициализации базы. `make run` запускает только приложение.
Сервис получает готовый `DATABASE_URL` из `app.env`; слой repository выполняет
только запросы чтения и записи в существующую таблицу.

HTTP 422 — некорректные данные, 404 — запись не найдена, 502 — ошибка соседа,
503 — ошибка базы. Обработка учебная: нет авторизации, автоматических повторов,
распределённой транзакции или реальной оплаты и отправки SMS.

## Доступ из браузера

`CORS_ORIGINS=null` в `app.env` разрешает учебному HTML-клиенту обращаться
к API при открытии страницы напрямую из файла (`file://`). Если клиент
размещён на HTTP-сервере, добавьте origin страницы через запятую, например
`CORS_ORIGINS=null,http://localhost:8080`, и перезапустите приложение.
